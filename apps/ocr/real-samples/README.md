### 这 6 张帮我改掉了 6 个错误 —— 这就是找你要真实截图的价值

| # | 我原来错在哪 | 你的截图暴露了它 |
|---|---|---|
| 1 | 金额只认**纯数字**，带 `¥` `￥` `+` `-` 就识别不到 | `¥0.10`、`-328.00`、`+50.00` **全部失败**；唯一成功的 `249.00` 恰好没符号 |
| 2 | 时间取了**手机状态栏的时钟**（截图时间，不是交易时间） | 六张全被读成 `1:41` 这类状态栏时间 |
| 3 | 日期**只认微信格式** `2026年9月21日` | 支付宝是 `2026-10-08`，**全部读不出** |
| 4 | 渠道靠"包含转账二字"判断 | 微信退款标题是「转账-退款」，被误判成**银行**；支付宝页面里没有"支付宝"三个字，也误判 |
| 5 | 把「**收款方**」当成收入标志 | 支付宝账单有字段「**收款方全称**」——它是**对方**（你付钱给谁）。结果**一笔支出被记成收入** |
| 6 | 金额取"最大的数字"，但没排除**优惠券面额** | 支付宝账单页 43 行里大半是广告（"2元全场券""天天秒杀"），金额一度被读成 **5** |

> **第 6 条最危险**：它会记出一笔**完全错误的金额**。而**"错"比"空"糟得多**——空着用户会填，错了用户可能直接点确认。

### 还剩的小瑕疵（不影响使用，弹窗里用户可以改）

| 现象 | 原因 | 处理 |
|---|---|---|
| 两张"转账成功瞬间"截图**读不到日期时间** | **截图里本来就没有**——那个界面不显示时间 | 留空并按今天填写，**弹窗里可改** |
| 支付宝转账截图的「备注」读成 `通知TA` | 该截图被滚动过，字段与值的对齐关系断了 | 留空更安全，后续用布局约束改进 |
| 支付宝账单读不到「单号」 | 单号在该页更靠下的位置 | 可选字段，缺了不影响记账 |
| 微信转账截图读不到「对方」 | 名字嵌在句子"待**张承昊**确认收款"里，不是独立字段 | 暂不处理（规则容易误伤） |

## 四、当前规则的已知局限

| 局限 | 说明 |
|---|---|
| **依赖固定字段名** | 微信/支付宝**改版就会失效**。所以规则要做成**可维护的配置**，而不是散落在代码里 |
| **状态栏按"顶部 8%"排除** | 不同机型状态栏高度不同。**灵动岛 / 安卓**的截图我需要验证 |
| **金额取"字号最大的数字"** | 如果某页有比金额更大的数字（如大额余额），会出错。目前没遇到 |
| **不判断真伪** | 按你的说明——**这只是省打字时间的快捷方式**，不负责核对真实性 |
