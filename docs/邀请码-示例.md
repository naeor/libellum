# 邀请码清单 · 格式示例

> 这是**示例文件**，进仓库，用来展示真实清单长什么样。
> **真实的邀请码清单在同目录的 `邀请码.md`，那个文件被 `.gitignore` 排除、不进仓库。**

## 为什么真实清单不进仓库

`.gitignore` 里有这几行：

```
docs/邀请码.md
docs/invite-codes.md
docs/邀请码-*.md
!docs/邀请码-示例.md
```

理由有两条，都很实际：

1. **仓库是开源的。** 一个进了仓库的邀请码，就是一个人人手里的邀请码——
   读到它的人可以直接注册一个账号；
2. **首批邀请码注册出来的是管理员。** 所有者要求把预留编号区间对应的账号标记为管理员
   （可以访问所有数据，含被弃置的账本），所以这批凭据的权限比普通邀请码更大。

> 另外，邀请码在数据库里是**明文**（`registration_invites.code`），不像恢复码那样存哈希。
> 它需要能被人读出来念给家人听，所以这份清单是**真正的凭据**。凭据不该进版本历史。

## 生成方式

```bash
# 单个（会预留账号编号）
pnpm invite:create "给妈妈"

# 批量，一个事务（预留编号连续，中途失败则一个码都不留）
pnpm invite:batch 98 --note "首批预留编号（管理员）"

# 把输出存成清单
pnpm invite:batch 98 > docs/邀请码.md
```

## 清单长什么样

```markdown
# 邀请码（98 个，一次性，每个对应一个账号编号）

生成时间：2026/10/10 16:45:12
备注：首批预留编号（管理员）

| # | 邀请码 | 账号编号 | 已使用 |
|---|---|---|---|
| 1 | `ABCD-EFGH-JKMN` | 10000002 | 否 |
| 2 | `PQRS-TUVW-XYZ0` | 10000003 | 否 |
| 3 | `2345-6789-ABCD` | 10000004 | 否 |
```

## 编号区间约定

| 区间 | 用途 |
|---|---|
| `10000000` | 所有者本人 |
| `10000001` | 第二个现有账号 |
| `10000002 – 10000099` | 首批邀请码（注册后为管理员） |
| `10000100` | **跳过**，让两段序列一眼可辨 |
| `10000101` 起 | 之后任何方式生成的邀请码，由服务器依次分配 |

完整说明见 `docs/邀请码.md`（不入库）与 `prisma/schema.prisma` 中 `User.accountNumber` 的注释。
