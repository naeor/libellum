## 为什么它们在这里（三种情况）

| 情况 | 含义 | 还能用吗 |
|---|---|---|
| **① 所在阶段已完成** | 那份设计决定是**已经做完那一轮**的规格 | ✅ 仍然准确，但**当历史读**——不要照它去"做"那件事 |
| **② 已被别的文档取代** | 内容**整体或大部分**搬进了另一份更权威的文档 | ⚠️ 以取代它的那份为准 |
| **③ 已作废 / 过程稿** | 实现方向被推翻、或只是当时的中间推导 | ❌ 只看"为什么当时那么想" |

**⚠️ 而"接近被废弃"不等于"可以删"**——
**这里每一份都记着"当时为什么这么定"，而那个理由往往比结论更值钱**
（`教训.md` 里反复出现的一句话：**"理由比结论更重要"**）。

## 两条注意

### 1. `.docx` / `.pdf` 永远在上一层，不在这里

**Markdown 是源文件，`.docx` 与 `.pdf` 是生成物。**
**所有生成物统一放在 `docs/` 根目录**（`pnpm docs:build` 生成），
**即使源文件在 `归档/` 里也一样**——导出名一直是这样，改导出名会让已有的下载与打印习惯失效。

- **改内容** → 改这里的 `.md`（但先问一句：它还该改吗？）
- **看阅读版** → 去 `docs/` 找同名 `.docx` / `.pdf`
- ⚠️ **`pnpm docs:build` 会重新生成上一层那些文件，覆盖手工改动。**

### 2. 这里**不再有新文件**

**做过一轮之后，那份设计决定就该进来**——但**判断"它是不是已经过时"是所有者的事，不是整理文档的人的判断。**
（相关教训：`教训.md` §1.4——**破坏性判据不能靠推断**；
以及 `README.md` 里那条：**"没有源文件、不在清单里"不等于"可以删"**。）
