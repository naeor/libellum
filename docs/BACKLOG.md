# Libellum · 后期待办与想法池

> **这份文档是做什么的**
>
> 开发过程中提出过很多"先不做，但别忘了"的想法。它们之前散落在对话、技术方案和开发日志里，
> 没有一个完整的整合。这份文档把它们**全部集中到一处**，并写清楚做判断所需的信息。
>
> **开发顺序由项目所有者决定**，这里只负责把信息整理齐，不替你做排序。
>
> 最后更新：2026-10-09

---

## 1. 怎么读这份文档

每一项都包含六列，回答"要不要现在做、先做哪个"时需要的全部信息：

| 列 | 含义 |
|---|---|
| **编号** | 便于讨论时引用，例如"先做 B2" |
| **想法** | 一句话说清是什么 |
| **为什么想要** | 提出时的意图（这决定了它值不值得做） |
| **前置条件** | 做它之前必须先有什么；没有前置的可以随时开工 |
| **规模** | 小＝半天内 / 中＝1–2 天 / 大＝3 天以上 |
| **表结构余地** | **最容易被忽略的一列**：现在不做，将来要不要改表并迁移真实数据 |

> 关于最后一列：**功能可以晚做，表结构不能晚定。** 如果一项待办需要新字段，而当时库里已经有真实账目，
> 那就不是"加个功能"，而是"在真实数据上做迁移"。所以每一项都标注了这一点。

## 3. 想法池：尚未排期

### A. 记账体验

| # | 想法 | 为什么想要 | 前置 | 规模 | 表结构余地 |
|---|---|---|---|---|---|
| **A1** | **自绘大键盘**：设置里可切换成大号数字键盘 | 系统键盘数字键小、易误触，还会被输入法遮挡；长辈手指粗 | 无 | 中 | 不需要（纯前端组件） |
| **A2** | **是否沿用上一笔可配置** | 现在固定"带入上次的分类/支付方式/币种"，有人可能不想要 | 无 | 小 | 不需要（前端默认值逻辑） |
| **A3** | **"复制上一笔"口径可调**：全局最近一笔 / 同分类最近一笔 | 记同一类支出时，"同分类的上一笔"更实用 | 无 | 小 | 接口预留查询参数即可 |
| **A4** | **登录即开始新记账**：开启后一进来直接进记账界面 | 少点一次；重度用户每天最常做的就是这个动作 | 无 | 小 | 不需要 |
| **B1** | **金额小数位按币种**：日元 0 位、科威特第纳尔 3 位 | 现在**所有币种统一按 2 位**处理，日元记 100 元会存成 10000 分 | 无 | 中 | **需要**：一旦有真实数据，改语义就得迁移历史金额 |

## 4. 已经明确否掉的想法（记下来，避免以后反复讨论）

| 想法 | 什么时候讨论过 | 结论与理由 |
|---|---|---|
| **二级分类** | 2026-10-08 功能核对 | **不做**。扁平分类 + 标签已经能覆盖"出差""可报销"这类跨分类场景，二级分类会让选择变慢 |
| **追踪账户余额** | 2026-10-08 功能核对 | **不做**。余额会牵出转账、对账、期初余额一整套逻辑，第一版不值得 |
| **专注/纯离线（数据只存浏览器）** | 2026-10-08 | **不做**。清缓存、换手机、手机丢失都会导致数据永久丢失；改为"离线优先 + 服务器权威" |
| **emoji 作为分类图标** | 2026-10-09 | **不用**。用户原话"显得不太正经"；保留 `icon` 列，将来改用 SVG 图标（见 B4） |
| **用编号替代用户名登录** | 2026-10-09 | **不做**。用户名＝微信号（唯一且可搜），昵称＝微信昵称（可重复），登录仍用用户名，编号只作社交标识 |
| **家人通过局域网访问做验收** | 2026-10-09 | **暂缓**。家人与用户不在同一网络；先由用户本人用局域网自测，家人测试留到上线后 |

## 5. 维护要求

1. 以后每新增一条"先不做但别忘了"的想法，**都追加到第 3 节**，并填齐六列。
2. 决定要做时，把它从第 3 节**移到第 2 节**（或 ROADMAP 的对应阶段），不要留在想法池里。
3. 讨论后明确否掉的，移到**第 4 节**并写明理由——**理由比结论更重要**，否则过几个月会有人（包括你自己）重新提出来再吵一遍。
