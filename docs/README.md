# docs 目录说明 · 先看这里

**这里有两类文件，看 `.pdf` / `.docx` 都是同一个东西的不同格式。**
Markdown 是**源文件**，Word 和 PDF 是**自动生成的阅读版**——不要直接改 Word/PDF，改了会被下次生成覆盖。

## 🖱️ 启动服务器

双击本目录下的 **`启动记账服务器.lnk`**。

- 已经开着的话，它会提示"已在运行"并直接打开浏览器，**不会报错**
- 窗口里会打印**手机该打开的网址**（形如 `http://192.168.0.184:5173`）
- **测试期间别关那个黑窗口**

> ⚠️ **如果你从别的地方（比如开发工具）启动服务器，它可能在闲置时被回收。**
> **从资源管理器双击这个快捷方式启动就不会**——它挂在资源管理器下面。

## 🔄 怎么重新生成 Word / PDF

Markdown 改完之后，运行：

```
pnpm.cmd docs
```

（或让 AI 助手重新生成。生成脚本在 `tools/md2docx.py`。）

> **PDF/DOCX 不进 Git 仓库**（见 `.gitignore`）——它们是导出件，随时可从 Markdown 重新生成。
> 如果你希望简历里直接能点开 PDF，把 `.gitignore` 里那两行删掉即可。

## 🚨 排查任何"页面行为不对"的第一步：**重启 dev server**

**2026-10-09 的教训。** 项目所有者在 iPhone 上点「拍照」时，
**每次都会回到明细页**。我依次怀疑并**排除了**：iOS 文件选择器、路由未注册、
路由未匹配、打包漏文件、Service Worker 缓存、导航逻辑——**六个假设全错**。

**真正的原因**：dev server 已连续运行数小时，**Vite 一直在提供陈旧（stale）的模块**。
磁盘上的 `BottomNav.tsx` 是正确的，但浏览器收到的是几小时前的版本。

**决定性证据**（这条命令应该第一个跑）：

```powershell
# 看 Vite「实际吐出」的模块，和磁盘上的对不对得上
(Invoke-WebRequest "http://localhost:5173/src/components/<组件>.tsx" -UseBasicParsing).Content |
  Select-String "关键 import"
```

当时的结果：模块里**用了 `Link`，却没有任何 `react-router` 的 import** →
`Link is not defined` → 全站崩溃。

**为什么会陈旧**：我分两步编辑同一个文件（先加用法、后加 import），
**中间那几秒 Vite 把一个坏模块推给了所有客户端，而它一直没被刷新掉。**

### 正确流程

| 步骤 | 命令 |
|---|---|
| 1. 停 | `Get-Process node \| Stop-Process -Force` |
| 2. **清 Vite 缓存（关键，别省）** | 删掉 `apps/web/node_modules/.vite` |
| 3. 启 | 双击 `docs\启动记账服务器.lnk`（从资源管理器启动进程才能存活） |
| 4. 验证 | 抓一次模块内容，确认改动在里面 |

> **推论：编辑一个文件时，尽量一次改完。** 分步编辑会制造出中间态的坏模块，
> 而 HMR 可能把它留在客户端上。

> **另一个推论：任何"手机上不对、电脑上对"的现象，先怀疑 dev server，再怀疑设备。**
