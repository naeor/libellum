## 📱 手机访问（含**必须的**一次性证书信任）

手机连同一个 Wi-Fi 后，地址是 **`https://192.168.0.184:5173`** —— **是 https，不是 http**。

### ⚠️ 为什么必须是 https

`getUserMedia`（录音）、`MediaRecorder`、`crypto.randomUUID`、Service Worker
**全都是"安全上下文"API**：浏览器**只在 https 或 localhost 上才定义它们**。

用 `http://192.168.0.184:5173` 打开时，页面看起来一切正常，但：

| 现象 | 真相 |
|---|---|
| 录音页说**"这个地址不是安全连接"** | 浏览器**根本没定义** `mediaDevices`。**不会弹权限提示——因为没有 API 可以提示** |
| `crypto.randomUUID is not a function` | 同一个原因（**这个坑踩过一次**） |
| 离线（Service Worker）不可用 | 同一个原因 |

> **这两个坑各浪费过一次排查时间，原因完全相同：URL 不是安全上下文，而提示说的是浏览器。**

### 一次性准备

```bash
pnpm dev:cert              # 生成开发用证书（自签，自动覆盖 localhost 与本机所有局域网 IP）
```

**然后双击仓库根目录的 `start-dev-lan.cmd`** —— 它以 https 启动并监听 0.0.0.0。

> ⚠️ **没有 `pnpm dev:lan` 这条命令**（这里以前写错了）：局域网启动的入口是那个 `.cmd` 文件，
> 它设置 `LIBELLUM_LAN=1` 并调用 `pnpm dev`；`apps/web/vite.config.ts` 据此决定监听地址与 https。
> **它也会检查证书**——缺 `apps/web/.certs/dev-cert.pem` 时会提示你先跑 `pnpm dev:cert`。

> ⚠️ **换了 Wi-Fi、或路由器重分了 IP 之后要重跑 `pnpm dev:cert`**——
> 证书里写着具体 IP，地址变了证书就对不上了。

### 手机上信任证书（**只做一次**）

自签证书浏览器不认，会拦一下。**这不是出错，是自签证书的正常表现。**

**iPhone / Safari**

| 步 | 做法 |
|---|---|
| 1 | Safari 打开 `https://192.168.0.184:5173` → 显示"此连接非私人连接" |
| 2 | 点 **「显示详细信息」→「访问此网站」**。页面能开了，但**录音仍然不可用**——还差第 3 步 |
| 3 | **设置 → 通用 → VPN 与设备管理** → 找到证书 → **安装** |
| 4 | **设置 → 通用 → 关于本机 → 证书信任设置** → 打开这个证书的开关 |
| 5 | 回 Safari 刷新 → 录音可用 |

## 🎙️ 语音记账（换服务器时要下载模型）

语音识别用的是 **whisper.cpp**（Python 绑定 `pywhispercpp`），默认 **`small` 档**。

| 项 | 说明 |
|---|---|
| **模型大小** | **488 MB**，首次运行时自动下载 |
| **存在哪** | `%LOCALAPPDATA%\pywhispercpp\pywhispercpp\models\`（服务器上是 `~/.cache` 附近） |
| **加载耗时** | 约 **38 秒**（所以服务是长驻进程，不是每次请求加载） |
| **转写速度** | 约 **1 秒音频 1 秒**（4 线程 CPU） |
| **⚠️ 部署提醒** | **新服务器上第一次录音会先下载 488MB**，可能要等一两分钟。**这不是卡死**，之后就一直很快 |

**换模型档位**（不用改代码）：

```bash
# Windows PowerShell
$env:LIBELLUM_WHISPER_MODEL = "base"    # 148MB，快但中文声调容易错
```

| 档位 | 大小 | 取舍 |
|---|---|---|
| `tiny` | 75 MB | 最快，中文基本不能用 |
| `base` | 148 MB | **曾经用过，把"午饭"听成"五份"** |
| **`small`** | **488 MB** | **当前默认**——2GB 内存跑得动，中文明显更好 |
| `medium` | 1.5 GB | 更准，但 2GB 服务器吃不消 |

> **"午饭" vs "五份"是声调区别**，正是小模型最容易丢的那类信息。
> 如果 `small` 还不够，`LIBELLUM_WHISPER_MODEL=medium` 可以在本机先试效果，再决定服务器配置。

## 🔄 怎么重新生成 Word（阅读版）

Markdown 改完之后，**在仓库根目录**运行：

```
pnpm docs:build
```

（或让 AI 助手重新生成。生成脚本是 `tools/build-docs.mjs`，它调用 `tools/md2docx.py` 与 `tools/md2pdf.py`。）

**⚠️ 四条要知道的**：

| # | 事实 |
|---|---|
| 1 | **命令是 `pnpm docs:build`**——**曾经写在这里的 `pnpm.cmd docs` 不存在**，照着敲会报错 |
| 2 | **同时生成 `.docx` 与 `.pdf`**（2026-10-13 起恢复 PDF）——**PDF 不再依赖 LibreOffice**：本机没有它，所以 `md2pdf.py` 直接从 Markdown 生成 |
| 3 | **文档清单是自动扫描的，不是手写的**——脚本走一遍 `docs/` 与 `docs/归档/`，**每份 `.md` 都产出同名阅读版**。<br>⚠️ **这条是为了不再犯同一个错**：以前那份手写清单漏过 `S8-冲突-设计决定.md`（承载全部冲突规则的那份），后来又漏了三份最新的设计文档。**需要手工维护的清单，迟早会过时。** |
| 4 | **生成物不进 Git 仓库**（`.gitignore` 里有 `docs/*.docx` 与 `docs/*.pdf`）——它们是导出件，随时可从 Markdown 重新生成 |

> **⚠️ 两个生成器各要一个 Python 包**：
> **`md2docx.py` 要 `python-docx`**、**`md2pdf.py` 要 `fpdf2`**。
> **缺哪个就跳过哪种格式**（脚本会分别探测并告诉你缺什么），**不会因为缺 PDF 就不生成 Word**。
>
> ```bash
> pip install python-docx fpdf2
> ```
>
> **⚠️ 而 PDF 不经过 LibreOffice**：这台机器上没有它，也没有 pandoc / wkhtmltopdf，
> 所以 `md2pdf.py` **直接从 Markdown 生成**（和 `md2docx.py` 同一条思路）。
> **字体取系统里的黑体 + 微软雅黑粗体 + Segoe UI Symbol**（第三样是必须的：
> **中文黑体没有 `⚠` `☑` `☐`**，而文档里几乎每段都有 `⚠️`）。

> **`恢复码.docx` 是唯一的例外**：它**没有 `.md` 源、也不由这个脚本生成**，
> **脚本被明确写成不会删它**（`build-docs.mjs` 里的 `NEVER_DELETE`）。
> ⚠️ **任何人整理文档时都会把它当孤儿——而它必须留着**，理由见下面「忘记密码」一节。

> **如果你希望简历里能直接点开这些阅读版**：把 `.gitignore` 里 **`docs/*.docx` 与 `docs/*.pdf` 那两行**删掉，它们就会被提交。

## 🔗 文档改完之后的自动检查

**Markdown 改完之后，在仓库根目录运行：**

```
pnpm check:docs
```

它跑两个常驻检查器，两个都只读、都很快：

| 脚本 | 查什么 | 为什么需要它 |
|---|---|---|
| **`tools/check-links.mjs`** | **每一份 Markdown 里的相对链接是否真的指向磁盘上存在的文件**（外链不查——"没网"和"链接坏了"是两件事） | ⚠️ **2026-10-13 那次整理里，`docs/档案/` 已并入 `docs/归档/`，但目录搬了、引用没搬**，根 README 里 4 个链接就此失效，**过了两轮才被发现**。跨文档引用正是"改了 A 就不会有人去看 B"的地方，所以它必须自动化 |

**一个因为正则写错而"零失败"的检查器，和通过长得一模一样。**

也可以单独跑：`pnpm check:links`。
> （当前是故意不提交的：都是二进制、改一次就多一份历史包袱。）

## 🚨 排查任何"页面行为不对"的第一步：**重启 dev server**

**2026-10-09 的教训。** 项目所有者在 iPhone 上点「拍照」时，
**每次都会回到明细页**。我依次怀疑并**排除了**：iOS 文件选择器、路由未注册、
路由未匹配、打包漏文件、Service Worker 缓存、导航逻辑——**六个假设全错**。

**真正的原因**：dev server 已连续运行数小时，**Vite 一直在提供陈旧（stale）的模块**。
磁盘上的 `BottomNav.tsx` 是正确的，但浏览器收到的是几小时前的版本。

**决定性证据**（这条命令应该第一个跑）：

```powershell
# 看 Vite「实际吐出」的模块，和磁盘上的对不对得上
(Invoke-WebRequest "http://localhost:5173/src/components/<组件>.tsx" -UseBasicParsing).Content |
  Select-String "关键 import"
```

当时的结果：模块里**用了 `Link`，却没有任何 `react-router` 的 import** →
`Link is not defined` → 全站崩溃。

**为什么会陈旧**：我分两步编辑同一个文件（先加用法、后加 import），
**中间那几秒 Vite 把一个坏模块推给了所有客户端，而它一直没被刷新掉。**

### 正确流程

| 步骤 | 命令 |
|---|---|
| 1. 停 | `Get-Process node \| Stop-Process -Force` |
| 2. **清 Vite 缓存（关键，别省）** | 删掉 `apps/web/node_modules/.vite` |
| 3. 启 | 双击 `docs\启动记账服务器.lnk`（从资源管理器启动进程才能存活） |
| 4. 验证 | 抓一次模块内容，确认改动在里面 |

> **推论：编辑一个文件时，尽量一次改完。** 分步编辑会制造出中间态的坏模块，
> 而 HMR 可能把它留在客户端上。

> **另一个推论：任何"手机上不对、电脑上对"的现象，先怀疑 dev server，再怀疑设备。**

## 🎫 生成邀请码

注册需要邀请码（项目开源但**不开放注册**）。两种方式：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **双击** | `docs\生成邀请码.cmd` | 最省事，窗口里会打印一串形如 `ABCD-EFGH-JKMN` 的邀请码 |
| **批量** | `pnpm invite:batch 98 --note "首批"` | 一次生成一批，一个事务，编号连续 |

> **每个码**会**预留账号编号**（生成时就定好，不是注册时才决定），用它的账号会拿到那个编号。
> 首批预留区间是 `10000002–10000099`，这些账号**是管理员**（能看全部数据、含弃置账本）。
> 之后的码从 `10000101` 起依次分配。
>
> ⚠️ **邀请码是明文保存的**（它需要能被念给家人听），所以**清单就是凭据**：
> 不要贴到任何公开的地方，也不要在 `.md` 里引用真实邀请码（这条踩过坑，见 DEVLOG §1.32）。

| 4 | 写入约 3 个月、118 笔账：日常消费、房租水电、工资、退款、理财；含人民币 / 美元 / 港币；**留 1 笔已删除的（墓碑）** 用来试"恢复" |

> **它故意不做的事**：**不会重复灌数据**——账号里已经有账目时，它会停下并告诉你（真想追加请加 `--more`）；
> **不写数据库、只走接口**——直连数据库会跳过校验、分类规则和幂等逻辑，那样造出来的数据证明不了任何事。
>
> 想给别的账号造数据，换 `--user` / `--password` / `--display` 即可。

## 🔑 忘记密码怎么办（恢复码）

**恢复码是唯一能自助找回密码的东西**，注册时只显示一次。

| 情况 | 做法 |
|---|---|
| 记得密码 | 登录后到「账户 → 设置 → 重新生成恢复码」，**新的生成后旧的立刻失效** |
| 忘了密码、**有恢复码** | 登录页 →「忘记密码」→ 填用户名 + 恢复码 → 设新密码。**恢复码只能用一次** |
| 忘了密码、**恢复码也丢了** | 只能由我直接改数据库（本地开发库），或重新注册一个账号 |

> ⚠️ **恢复码是明文，别放进 Git。** 仓库的 `docs/*.docx` 已被 `.gitignore` 排除，
> 但如果把恢复码写进任何 `.md` 或聊天里发给别人，它就等于公开了。

### ⚠️ `docs/恢复码.docx` —— **请勿删除**（所有者明确要求保留）

**这是全库唯一一份"没有 `.md` 源文件、也不由 `pnpm docs:build` 生成"的文档**，
所以它**不会**出现在上面的索引里，也**不在生成清单里**——而且
**`tools/build-docs.mjs` 被明确写成不会删它**（`NEVER_DELETE` 那份名单）。
**任何人（包括 AI）在整理文档时都会把它当成"孤儿文件"——而它必须留着。**

**所有者 2026-10-11 的原话**：

> **"请保留那个恢复码，它是一份说明性文件，也是我现在这个账号的恢复码——至少曾经是。
> 某个 AI 智能体在工作时，把我曾经的账号删除了并注册了一个新账号，所以他理论上确实没太大作用，
> 但我想留着做个纪念。"**

| 项 | 值 |
|---|---|
| **性质** | **说明性文件 + 一份历史凭据**（那个账号已不存在，所以它很可能**已经无效**） |
| **为什么不删** | **所有者要留作纪念**——这是一个人的理由，不是技术判断 |
| **为什么不能当"当前恢复码"用** | 它属于**已经被删除的旧账号**；当前账号的恢复码以重新生成的那一份为准 |
| **⚠️ 给接手者/AI 的规矩** | **不要把它当孤儿清理掉，不要把它并入生成清单，也不要"顺手"删掉它。** |

> **⚠️ 而这一条本身也是个提醒**：**"没有源文件、不在清单里"不等于"可以删"**——
> **只有所有者能判断一样东西是不是废的。**（相关教训见 `教训.md` §1.4：破坏性判据不能靠推断。）

## 📴 离线能用吗？要不要打包成 App？

**能，而且不需要打包。** 这一节是为了回答一个很自然的问题。

### 数据真的在本机

| 直觉 | 实际 |
|---|---|
| "网页只是缓存，没下到本机" | **IndexedDB 是真实数据库**，就在浏览器的数据目录里，**和原生 App 存文件是同一件事** |
| "打包成 App 就能离线" | **APK / iOS 里的 WebView 用的是同一套 IndexedDB**，**存储机制完全一样**，不会多出任何能力 |

> **Web 在这里不是"原生应用的薄版本"，而是"同一套安排换了安装方式"。**
> 打包能换来的是**图标、推送、应用商店**——**不是离线能力**。

### ⚠️ 但有一件真事：浏览器默认会回收存储

| 情况 | 后果 |
|---|---|
| 存储是 **best-effort**（默认） | 空间紧张时**可能被回收** |
| **Safari** | 对**七天未访问**的站点会清除存储 |

**所以启动时会申请"持久化存储"**（`navigator.storage.persist()`）。
浏览器答应之后就不会自己回收。**如果它拒绝了，应用会在离线状态栏里告诉你**
（"浏览器未承诺长期保留"）——**这件事应该在平时知道，而不是在飞机上发现。**

### 历史记录会自动存到本机

应用启动后**会自动把你全部历史（默认回溯 5 年）按月取回并存到本机**。
屏幕上会显示进度（"正在把历史记录存到本机（12/60 个月）"），**完成后再启动几乎不花时间**。

**流量网络下不下载**——整本账走流量不该悄悄做；连上 Wi-Fi 会自动继续。

### 下载管理（账户 → 下载管理）

在里面可以按**月**看到本机存了什么：

| 列 | 含义 |
|---|---|
| **已下载** | 这个月在这台设备上，离线能看；显示**笔数与占用空间** |
| **未下载** | 还没取；显示**预计占用**（按已下载月份的平均值估） |
| **永不下载** | **这是你的决定**，填充会跳过它，不会再自动取 |

每个月可以**单独控制**：「删除已下载」（真正释放空间）／「永不下载」／「改为下载」。
点「下载全部」可以立刻补取。

### 现在的状态

> **⚠️ 先把"离线"这个词读准确**：**离线覆盖的是记账主路径**（记 / 改 / 删 / 看 / 统计），
> **不是"每个功能都能离线"**。**拍照与语音需要服务器**（OCR 与 whisper 都在服务器上跑），
> 所以它们**离线不可用是设计决定**（所有者 2026-10-11 定稿："我已经确定不做离线拍照和语音了"）。
