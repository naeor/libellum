## 1. ⚠️ 开工前必读的三件事

### 1.1 `docs/教训.md`——**先读 §0 的三条**

**这个项目最贵的一课是一个花了四个小时的 bug**，而它已经汇总成一份文档。
**如果你只能读一样东西，读 `教训.md` §0。**
**而 §8.11 和 §8.12 是本轮新增的**，直接关系到你最容易犯的错。

### 1.2 所有者定的规矩：**每一次改动都要升版本 + 写进文档**

> **"以后你每次更新一次，就把版本号加1。"**
>
> **"每次更改都要做版本更新，并且写清楚这次版本更新做了什么，写入文档。"**

**做法**：`apps/web/src/lib/version.ts` 最后一段 +1，
并在 `docs/版本记录.md` **追加一条**（改了什么 / 为什么 / **怎么验证的**）。
**规则原文在 `版本记录.md` §1。**

### 1.3 所有者定的工作方式（2026-10-11 明确）

> **"我在明确说明代码逻辑之后，你可以直接提出反对或者修改意见（这里畅所欲言就好，
> 可以考虑到尽可能多的情况和风险）。但一旦整个计划被敲定，在执行时必须要完美严谨的只执行确认好的逻辑，
> 不添加任何东西。"**

**⚠️ 而这条规矩是被一次真实的失败换来的**：**他描述清楚了判定逻辑，
而我自作主张把一条"版本号捷径"留在里面，它把整个冲突检测吞掉了**——见 `教训.md` §8.11。

**所以**：
**讨论阶段尽管反对、尽管提风险；一旦敲定，只执行，不加、不减、不"顺手优化"。**

## 2. 怎么把它跑起来

### 2.1 前置

| 需要 | 说明 |
|---|---|
| **Node + pnpm** | 见根 `package.json`；pnpm workspace |
| **PostgreSQL 17** | 测试库与开发库**是分开的** |
| **`.env`** | **不进 git**（`DATABASE_URL` 等） |

**数据库连接串**（本机开发环境）：

```
DATABASE_URL=postgresql://ledger:jTtEIVfdXRmLxel789nBoKOhHW2w@127.0.0.1:5432/ledger_dev?schema=public
TEST_DATABASE_URL=…/ledger_test…
```

**⚠️ 测试库要单独跑一次 `prisma migrate deploy`**，否则 API 测试会因为缺表失败。

### 2.2 常用命令（**都在仓库根目录跑**）

| 命令 | 作用 |
|---|---|
| `pnpm typecheck` | 三个包的类型检查 |
| `pnpm -r test` | 全量测试（shared / web / api） |
| **`pnpm check:build`** | **真实构建**——**见下方警告** |
| `pnpm docs:build` | 把 11 份 markdown 生成 `.docx` |
| `node tools/check-modules.mjs` | 每个源码模块能否独立编译 |
| `pnpm db:generate` / `pnpm db:deploy` | Prisma 生成 / 应用迁移 |

### 2.3 ⚠️ **`pnpm check:build` 不能省**

**类型检查和单元测试都拦不住"整个应用起不来"。**
**这个项目真的发生过一次**：一条 CSS 规则放进了 Tailwind 的 `@theme` 块
（它只允许自定义属性或 `@keyframes`），**于是 Vite 用错误浮层替换掉整个应用，
所有路由包括登录页都变成一张错误图**——**而当时 `typecheck` 全过、650 条测试全过。**

**见 `教训.md` §8.10。** **所以**：**每次提交前跑 `pnpm check:build`。**

### 2.4 开发服务器与真机访问

| 服务 | 地址 |
|---|---|
| **API** | `http://127.0.0.1:3000` |
| **Vite（局域网 HTTPS）** | `https://192.168.0.184:5173`（**证书在 `apps/web/.certs/`，不进 git**） |

**⚠️ Service Worker 只能在 https 下测**，所以必须走局域网 HTTPS 那个地址，不能用 `localhost`。

**⚠️ 真机测试是这个项目的常态**：**很多 bug 只在 iPad Safari 上出现**

## 3. 代码长什么样

### 3.1 目录

```
apps/api        Fastify 5 + Prisma 7 + PostgreSQL 17
apps/web        React 19 + Vite 8 + Tailwind 4 + TanStack Query 5
apps/ocr        识别服务
apps/voice      语音服务
packages/shared 前后端共用类型与校验
docs            设计文档（markdown 是源，.docx 是产物，且不进 git）
tools           证书生成、模块检查、构建检查
```

### 3.2 ⚠️ 四条会咬人的约定

| 约定 | 说明 |
|---|---|
| **金额一律是整数最小单位** | 元以"分"存（`amountCents`）。**永远不要引入浮点** |
| **`exactOptionalPropertyTypes: true`** | 可选属性写 `undefined` 会报错。**可选 prop 的类型要显式 `\| undefined`** |
| **时间要比较"瞬间"，不能比较字符串** | 家里有 UTC-7 和 UTC+8 两种记录时，**ISO 字符串排序是错的**——用 `Date.parse` |
| **`categoryName` / `version` 不参与冲突比较** | 前者是派生显示字段，后者是记账用的 |

### 3.3 离线层的核心（**改这里之前先读 `档案/S8-冲突-设计决定.md`**）

| 文件 | 作用 |
|---|---|
| `lib/offline/localLedger.ts` | **权威存储**：`ledger-months`（账目）+ `ledger-marks`（印记）；**外部 store + `useSyncExternalStore`** |
| `lib/offline/sync.ts` | `syncAll()`（从印记推导要发什么）、拉月份、拉冲突 |
| `lib/offline/write.ts` | 新建 / 修改 / 删除 / 解决冲突 |
| `lib/offline/conflictChoices.ts` | **冲突界面的候选项**（来自服务端的 `claims`） |
| `lib/offline/device.ts` | 本机标识（冲突记录要写"哪两台设备"） |
| `lib/ledgerView.ts` | 界面用的账目合并（**服务器那份优先，本机未同步的保留**） |

**⚠️ 而这一条是这一层最容易犯的错**：

> **绝不用 React state 承载"界面要读的离线数据"。**
> **必须走模块级外部 store + `useSyncExternalStore`**——
> **因为曾经发生过"`setState` 被调用了、而 iPad Safari 上没有重渲染"，那花了四个小时。**

## 4. 冲突：所有者定的规则（**改它之前必须读懂**）

**完整版见 `档案/S8-冲突-设计决定.md`。这里是提要。**

### 4.1 判定只用三个值，**不用版本号（这是硬的）**

| # | 条件 | 结论 |
|---|---|---|
| **1** | `base == 服务器当前值` | ✅ **接受并写入**（普通在线编辑） |
| **2** | `wanted == 服务器当前值` | ✅ 不写（**"60 和 60 不弹窗"**） |
| **3** | `wanted` 在服务器历史值里 | ✅ 不写（**"直接改为 70"**） |
| **4** | 其余 | ⚠️ **冲突** |

**⚠️ 判定函数 `judge()` 的签名里没有版本号参数**——
**这是刻意的：能被写出来的错误，迟早会被写出来。**

### 4.2 其他几条同样硬的

| 规则 | 内容 |
|---|---|
| **时间不参与判定** | `occurredAt` 不在 `CONFLICT_FIELDS` 里，**但照样写入** |
| **冲突活在服务器上** | 一台设备处理掉，所有设备都不黄了 |
| **"自动合了哪些"必须显示** | 否则用户不知道机器替他决定了什么 |
| **解决冲突时本地先生效** | 先清印记、改值、颜色立刻正常，**再发消息给服务器** |
| **没有冲突一律以服务器为准** | 包括"本地落后"的情况 |

## 5. ⚠️ 这一层最容易踩的五个坑（都有真实出处）

| # | 坑 | 出处 |
|---|---|---|
| **1** | **用 React state 承载离线数据** | 四小时 bug，`教训.md` §0.1 |
| **2** | **"判据"和"界面看的东西"不是同一个** | 冲突界面"零个选项"，`教训.md` §8.12 |
| **3** | **被否决的想法留在代码里** | 冲突检测整个失效，`教训.md` §8.11 |
| **4** | **只跑 typecheck + test 就提交** | 整个应用起不来，`教训.md` §8.10 |
| **5** | **脚本化编辑没有 grep 核实** | 明细页整页空白，`教训.md` §8.1 |

**⚠️ 第 5 条值得单独说**：**这个项目有多次"编辑看起来成功、实际没落地"**。
**所以规矩是**：**每一次编辑之后，用 grep 确认那一行真的在文件里。**
**⚠️ 而 PowerShell 的 `String.Replace(old, new, count)` 重载不存在**——
**它会把所有匹配都换掉**（我因此一次性改坏了 25 处，`版本记录.md` 里留了记录）。
**所以：改源码优先用编辑工具，不用 shell 脚本做字符串替换。**

## 8. 和所有者打交道

**这一节是给下一个 AI 的，而且它可能是最有用的。**

### 8.1 他会给出非常准确的判断，**要当真**

**这个项目里好几次是他比我先找对方向**：

| 他的原话 | 后来的结论 |
|---|---|
| **"在进入明细态时右上角的三个按钮很难被点击到，似乎是判定的问题"** | **确实是判定问题**——按钮上移 4px，升进了上方横幅 `z-index` 更高的那条带里 |
| **"至于'判定里完全不需要版本号'，这个似乎是你早期提出的一点，但被我否决之后，它隐藏在你的思路里"** | **完全正确**，而那就是冲突检测失效的根因 |
| **"我想没有哪个程序会弹出一个弹窗让人选择数字是 60 还是 60"** | **一句话定义了规则 2** |

**⚠️ 所以他说"似乎是这样"的时候，先按他说的去查，而不是先解释为什么不可能。**

### 8.2 他要的是结果，不是过程描述

- **报告要说清**：**版本号、改了什么、怎么验证的**；
- **⚠️ 而他明确要求过"略微精简诊断"**——**不重要的诊断不要写出来**；
- **而"未解决"必须写成未解决**：`版本记录.md` §1.3 有一条：
  **"一个把'未解决'写成'已解决'的记录，比没有记录更糟。"**

### 8.3 他会用中文，而**回复也用中文**

**他的原话要求过**：**"记得用中文回复，并且思考过程也用中文。"**

### 8.4 ⚠️ 一条我给下一个 AI 的实话

**这一轮我表现不好**：**我在他已经说清楚规则之后还自己加了东西，而加的那条把主要功能弄坏了。**
**代价是四个多小时和很多次来回。**

**所以**：**当他说"我就是这个逻辑"的时候，不要再问"要不要顺便……"。**
**当他没说的，不要加。当他不确定的，问他。**

**⚠️ 而他会因为反复失败而急躁——那是正常的**，
**而这时的正确做法不是道歉更多次，是"少做、做对、把结果说清楚"。**

## 9. 一份最短的开工清单

```

2. 读 docs/交接.md（本文）§1.3、§4、§5
```
