> 2. **代理会改写 Host，这会破坏依赖 Host 的安全判断。** 这类问题在 `localhost` 下永远测不出来，**必须用真实访问路径验证**——这也是为什么每次改网络相关配置都要实际请求一遍，而不是"看起来对就行"。

### 3.1 如何打开本地网站（随时可用）

**地址固定不变**：<http://localhost:5173>（API 在 <http://127.0.0.1:3000>）

> ⚠️ **网站打不开 ≠ 网站坏了。** 这是一个**本机开发服务器**，只有在你的电脑上把它启动起来才存在。关掉启动窗口、或电脑重启之后，`localhost:5173` 就打不开了——**地址从头到尾没有变过**。

**启动方式（任选一种）**

| 方式 | 操作 | 手机能访问吗 |
|---|---|---|
| **推荐：双击** | 打开 `C:\Users\ZhuanZ（无密码）\Desktop\工作\记账程序\`，双击 **`start-dev.cmd`**；约 15 秒后浏览器自动打开 | 不能（只绑本机） |
| **手机测试** | 双击 **`start-dev-lan.cmd`**；窗口里会直接打印手机该打开的网址 | **能**（手机需连同一个 Wi-Fi） |
| 命令行 | 在项目目录运行 `pnpm.cmd dev`（PowerShell 里**必须带 `.cmd`**，因为执行策略禁止运行 `.ps1`） | 不能 |

> **为什么默认不暴露到局域网**：在公共 Wi-Fi 上，任何同网设备都能访问开发服务器；默认只绑本机更安全。需要手机测试时再用局域网脚本。

**停止方式**：关掉那个黑色窗口，或在窗口里按 `Ctrl+C`。

**启动成功的标志**

```
Server listening at http://127.0.0.1:3000      ← API 已启动
  VITE v8.x  ready in ... ms
  ➜  Local:   http://localhost:5173/           ← 网站已启动
```

**打不开时的排查顺序**

1. **先重启开发服务器**（关掉那个黑色窗口，再双击 `start-dev.cmd`）—— **开发服务器跑久了可能悄悄返回旧版本的模块，表现为白屏**
2. 那个黑色窗口还在吗？不在就是服务没启动 → 双击 `start-dev.cmd`
3. 窗口里有没有红色报错？有的话把内容发给我
4. 提示 `EADDRINUSE`（端口被占用）→ 说明服务其实已经在跑，直接打开 <http://localhost:5173>
5. 数据库没启动 → `Win+R` 输入 `services.msc`，确认 `postgresql-x64-17` 处于"正在运行"

> **白屏怎么办**：现在应用装了**错误边界**，真正的代码错误会显示错误信息并提供"刷新页面"。
> 如果**连错误信息都没有、整页空白**，那基本可以断定是环境问题 —— 按上面第 1 步重启服务即可。

> **承诺**：以后每当我需要**关闭**这个本地服务、或它监听的**地址/端口发生变化**，都会在对话里明确说明，并同步更新本节。

### 5.2 备案与大陆访问（调研 #3，2026-10-08）

| 结论 | 要点 |
|---|---|
| 境外免 ICP 备案 | 阿里云官方 FAQ 明文：解析指向境外服务器（如中国香港）**无需 ICP 备案** |
| **公安联网备案** | 依《计算机信息网络国际联网安全保护管理办法》，**服务器在境外但向大陆提供服务**须在开通起 **30 日内**办理；个人可扫码实名，审核约 2–3 天；备案号须展示在网页底部 |
| 个人 ICP 备案 | 论坛型交互站点已无法办理（BBS 前置审批停止）；交互式服务存在审核障碍 |

## 10. 附录：GitHub 设备码授权到底做了什么

（于 2026-10-08 15:11:38 完成；项目所有者事后询问，特此记录）

**为什么需要授权**：`gh`（GitHub CLI）和 `git push` 都要代表你的账号向 GitHub 写数据。GitHub 不接受匿名写入，所以必须有一次"证明你是 naeor"的动作。

**那一步具体发生了什么**

1. 我在本机运行 `gh auth login --web`，CLI 向 GitHub 申请一个**一次性设备码**（形如 `793A-62EF`），并给出地址 `https://github.com/login/device`。
2. 你在浏览器打开该地址、登录自己的 GitHub 账号、输入这个码，再点"授权"。
3. GitHub 确认后，把一个 **OAuth token** 发回本机 CLI；CLI 把它存进 **Windows 凭据管理器（keyring）**。
4. 此后所有 `git push` 与 `gh` 命令都用这个 token 证明身份，**不必再输密码或验证码**。

**授权范围（判断风险的关键）**：`gh auth status` 显示 token 权限为 `repo`、`gist`、`read:org`。

| 权限 | 含义 |
|---|---|
| `repo` | 可读写你**所有**仓库的代码与设置（不只 libellum） |
| `gist` | 可读写你的代码片段 |
| `read:org` | 可读取你所属组织的成员信息 |

**需要知道的三件事**

1. 这个 token **只存在你这台电脑上**：不在聊天记录里，也没进 Git 仓库。
2. 它**不等于你的 GitHub 密码**：不能用来登录网页、改密码、改邮箱。你可以随时在 GitHub 的 `Settings → Applications` 里撤销。
3. **撤销后**：我这边再 `git push` 会重新要求授权（再走一次设备码流程）。撤销安全且可逆。

**为什么没有用手动粘贴的个人访问令牌（PAT）**：PAT 会以明文出现在聊天记录和命令历史里。设备码方式把凭据直接交给系统凭据管理器，更安全也更省事。

**风险提示**：`repo` 权限覆盖你名下所有仓库，范围偏大。若日后想收紧，可改用只对单个仓库生效的 fine-grained token，或安装限定仓库范围的 GitHub App。对当前阶段（单人开发、公开仓库）风险可接受。

## 11. 工程技巧与可复用做法

> 这一章收集**在别处也能用上**的做法。项目所有者要求把技巧记下来，所以这里不写"这次改了什么"（那在第 1 章），
> 只写**为什么这么做、什么情况下值得复用**。

### 11.1 组件测试：静态渲染成字符串，不引入 jsdom

**做法**：用 `renderToStaticMarkup`（来自 `react-dom/server`）把组件渲染成 HTML 字符串，然后对字符串做断言。

```ts
const html = renderToStaticMarkup(<ChartFrame height={160} title="趋势" notice="暂无记录">…</ChartFrame>);
expect(html).toContain("暂无记录");
```

**好处**：不需要 jsdom、不需要 `@testing-library/react`、不需要配置测试环境，**跑得极快**（55 个测试 0.7 秒）。

**前提**：组件在**没有副作用**的情况下也要能渲染出有意义的输出。例如 `useElementWidth` 在测量发生前返回一个**合理默认宽度**，
所以静态渲染能画出完整图表。这个"默认值"同时也是服务端渲染场景下正确的行为——**为测试做的设计，恰好也是为健壮性做的设计**。

**适用范围**：图表、纯展示组件、任何"输入决定输出"的组件。
**不适用**：需要真实交互（点击、输入、焦点）、需要真实测量、需要异步副作用的组件。

### 11.2 把最容易出错的规则集中到一个纯函数里

**做法**：`summariseSeries` 一个函数判定"这组数据是什么状态"（空 / 全零 / 单一分类 / 含负值 / 有极值），
所有图表都调它，而不是各自判断。

**为什么**：五个图表各自写一遍空数据判断，就会有五种不同的处理，**其中至少一种会忘记处理某个边界情况**。
集中之后，**边界情况只需要想清楚一次**，而且**可以单独测试**。

**推广**：任何"多个组件都要处理同一类边界"的场景都适用——把判定抽成纯函数，组件只负责根据判定结果渲染。

### 11.3 图表按真实像素绘制，不缩放 viewBox

**做法**：用 `ResizeObserver` 量出容器宽度，按 1:1 像素坐标绘制，`viewBox` 与实测宽度一致。

**为什么不缩放**：`viewBox` + `width="100%"` 会让整个图形（**包括文字**）一起缩放。
在窄屏手机上，图形变小没关系，**但坐标轴标签变小就读不清了**——而文字恰恰是最不能缩的部分。

**代价**：需要一个测量步骤，首帧会先用默认宽度渲染。**用合理的默认值 + 下一帧重测**即可，用户看不出来。

### 11.4 开发验证页：用 `import.meta.env.DEV` 守卫

**做法**：为复杂的基础组件建一个**只在开发模式存在**的页面（如 `/lab/charts`），用**故意刁难的数据**把每种能力都画一遍。

```ts
const ChartLabPage = import.meta.env.DEV ? lazy(() => import("./pages/ChartLabPage.js")…) : null;
```

**为什么值得**：
- 基础组件在**没有真实业务数据**时无法验证；验证页让它可以被"看见"
- 边界情况（极值、空数据、全零）在真实数据里**很难等到**，在验证页里**随时可见**
- 生产构建时 `import.meta.env.DEV` 被替换为 `false`，**整个页面被消除，不进包**

**验证方式**：对比构建前后的产物体积，确认**没有变化**。

### 11.5 先用一次真实请求验证安全判断，再谈"看起来对"

**由来**：见 §1.18——Vite 代理的 `changeOrigin` 改写了 Host 头，导致同源请求被误判为跨站。
**这个问题在 `localhost` 下永远测不出来**，因为两边恰好都是 `localhost:5173`。

**做法**：任何与"来源 / 主机 / 域名 / 端口"相关的逻辑，**必须用真实的访问路径请求一遍**，而不是只看代码。

### 11.6 空状态文案要像产品在陈述事实

**由来**：项目所有者指出"这个时间段有记录，但金额都是 0"**过于口语化**。

**规则**：
- 用**陈述句**，描述事实，不表达情绪、不猜测用户意图
- 不用"都是""还没有""没什么"这类口语词
- 说明**为什么这里是空的**，而不只是"没有数据"——"暂无记录"和"记录金额均为零"是两件不同的事
- 结尾用句号

**并且写进测试**：把"不得出现的口语词"断言成测试，**规范才不会随时间滑坡**。
