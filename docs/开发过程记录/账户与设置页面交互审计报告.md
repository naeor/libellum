## 1. 底部「账户」Tab 点击后进入什么路由、渲染哪个组件、是否重定向

### 1.1 点击链（逐步）

| 步骤 | 源码位置 | 实际行为 |
|---|---|---|
| 1 | `BottomNav.tsx:101-108` | `TABS` 共 5 项，最后一项 `{ to: "/me", label: "账户", icon: PersonIcon }`（第 107 行）。 |
| 2 | `BottomNav.tsx:405-411` | 普通 Tab 渲染为 `<button type="button">`，`onClick` 调用 `onNavigate(tab.to)`；当前项带 `aria-current="page"`（第 412 行）。 |

| 5 | `App.tsx:112-119` | `RequireAuth`：`status === "loading"` 时渲染 `Splash`（`:106-110`），`!user` 时 `<Navigate to="/login" replace />`（第 116 行），否则原样渲染 children。 |

### 1.2 结论

- 登录状态下点击「账户」：进入 **`/me`** → 渲染 **`MePage`** → **没有重定向**（`App.tsx:201-208` 不含 `<Navigate>`）。

- `MePage` 内部还有一层 `if (!user) return <></>`（`MePage.tsx:28`），正常路径被守卫挡住，不会触发。
- 不存在 `/account` 路由：手动访问会落到通配路由 `<Navigate to="/" replace />`（`App.tsx:310`）。
- 对照：`/books` 才是显式重定向到 `/start`（`App.tsx:249-250`，注释说明了保留原因）；`/me` 没有这种重定向。

### 4.1 「默认币种」的数据流与已知矛盾（按代码路径推断）

- 当前值 `user?.defaultCurrency ?? "CNY"`（`SettingsPage.tsx:65`）。
- 提交是 `PATCH /auth/me`（`queries.ts:174-175`）。
- 但 `onSuccess` 只写了 `client.setQueryData(["me"], data)` 并 `invalidateQueries(["me"])`（`queries.ts:176-179`）。**全仓没有任何组件订阅 `["me"]` 这个查询键**（`grep` 只有这两行）。
- `AuthProvider.user` 是独立的 React state（`AuthProvider.tsx:80`），由 `reload()`/`login()`/`register()` 等 `setUser` 更新（`:128`、`:184`、`:236`、`:247`），**不会因为这次 PATCH 而变**；下次更新要等 60 秒定时器或窗口聚焦（`:48`、`:176-209`）。
- 因此：用户会同时看到「已保存。」（`SettingsPage.tsx:104`）**与旧币种仍高亮**（`:65` 的 `current` 未变）；其它读 `user.defaultCurrency` 的地方同样延迟——`DetailPage.tsx:190`、`StatsPage.tsx:58`、`:83-90`、`ExportPage.tsx:378`。

### 5.2 「返回」按钮的真实算法（不是简单用 `backTo`）

`InnerPage` 只有一个「← 返回」控件（`Layouts.tsx:239-249`，带 `data-back-control`），点击调用 `useGoBack(backTo)`（`Layouts.tsx:213-214`）。优先级：

1. **10 秒内第 4 次按返回** → `navigate("/", { replace: true })` 直接回明细页（`connectivity.ts:67-70`；常量见 `backFallback.ts:21-22`）。
2. **`location.state.from` 存在** → `navigate(from)`（`connectivity.ts:76-79`）。
3. **有历史**（`location.key !== "default"`）→ `navigate(-1)`（`connectivity.ts:81-84`）。
4. **都没有** → `navigate(fallback)`（`connectivity.ts:86`）。

由此产生的实际差异：

- 正常点击进入时，返回的是**浏览器历史上一页**，不一定是声明的父页；`backTo` 只在深链/无历史时生效。
- 分类/支付/标签三页的真实入口是账户页（`MePage.tsx:36-38`），`backTo` 却写 `/settings`（`ManagePages.tsx:170`、`:281`、`:396`）。**直接打开链接时返回会落到从未经过的设置页**。
- 关于/法律页的 `state.from` **只有账本空间 footer 会传**（`LedgerSpacePage.tsx:639-647`）；从设置页打开关于时 `go`（`SettingsPage.tsx:62`）不传 state，`from` 为 null，只能靠历史；`backNavigation.test.ts:52-79` 只断言了这三处 footer 链接与两个 fallback 字符串，没覆盖设置页入口。
- 下载管理·更多用 `replace`（`DownloadMorePage.tsx:219`），与其它页的「历史 -1」不同。
- 单月下载页有**两个**返回控件：页头「← 返回」（`MonthDownloadPage.tsx:91` → `backTo`）与页内「返回下载管理」（`:218-224`）。
- `/start` 既不用 `TabPage` 也不用 `InnerPage`：**没有页头返回**，只能点右上角账户头像（`<a href="/me">`，`LedgerSpacePage.tsx:375-393`，且要在海浪收起后可点，`:390`）或用浏览器返回。
- `InnerPage` 的 `backTo` 默认值是 `"/"`（`Layouts.tsx:201-202`）。

### 5.3 面包屑

代码中**没有面包屑组件**。`InnerPage` 头部只有标题与可选副标题（`Layouts.tsx:253-256`），返回按钮文字固定为「返回」（`:248`）。层级信息完全依赖用户记忆。

### 7.2 结论：存在混用，而且不只是同义词问题

1. **同一条指引，两页说法相反（严重）。** 谁想知道「注册用的邀请码在哪」：
   - `LedgerInvitePage.tsx:259` 写：**「在「账户」页面。」** ← **错**，账户页已无该入口（`MePage.tsx:100-114` 只剩注释）；
   - `StartBookPages.tsx:365` 写：「在「**设置 → 账号安全**」。」 ← **对**。
   同一产品里两个页面把用户指向两个不同位置，其中一个是死路。
2. **「账户」是导航容器，不是账户资料页**：一个 8 行扁平列表同时承载身份、分类/支付/标签管理、账本空间、下载管理、软件更新、设置（`MePage.tsx:34-50`）。

4. **「账本」一词指两个页面**：`/start`（账本空间/列表）与 `/ledger`（当前账本的 Tab）；账户页把它叫「我的账本」，底部叫「账本/协作」。

## 9. 手机与桌面布局的结构差异（响应式类名 / 条件渲染）

### 9.1 结论

**代码没有为桌面做任何结构分支。** 手机与桌面是同一套单列布局，差别只来自页面框架类型（`TabPage` / `InnerPage` / 账本空间自绘）与浏览器宽度带来的留白。

| 维度 | 手机 | 桌面 | 源码 |
|---|---|---|---|
| 全局壳 | `AppShell` 只提供记账菜单 context，**不渲染侧边栏/顶栏** | 同左 | `Layouts.tsx:81-110` |
| 账户页框架 | `TabPage`：`h-dvh`、中部滚动、底部 `BottomNav` | 同左；内容列 `max-w-md` 居中，两侧留白 | `Layouts.tsx:155`、`:159-163`、`:179-183` |
| 设置/二级页框架 | `InnerPage`：`main max-w-md`，**无底部导航** | 同左，没有侧边栏替代 | `Layouts.tsx:235` |
| 底部导航 | 全宽 `<nav>`，内部 `max-w-md` 居中；`pb-[env(safe-area-inset-bottom)]` | 同左，仍在底部；`border-t` 横贯整个屏幕宽度，条目仍居中 | `BottomNav.tsx:237-239`、`:293`、`:366` |
| 绿色标题带宽度 | 跟着 `max-w-md` 容器 | 桌面下仍是约 448px 的一条，两侧是页面底色 | `MePage.tsx:60-64`（在 `TabPage` 的 `max-w-md` 内）、`Layouts.tsx:162` |
| 弹层形态 | 底部抽屉/居中对话框 | 同左（如账本管理抽屉 `fixed inset-x-0 bottom-0 mx-auto max-w-md`） | `BookManageSheet.tsx:257`、`ConfirmDialog.tsx:85-97` |

| 宽度断点 | **无** `sm:`/`md:`/`lg:` 结构类；唯一一个 `sm:w-auto` 在分享组件，与账户/设置无关 | 同左 | `ShareSection.tsx:209` |
| 条件渲染 | 只有「菜单展开 / 离线提示 / `onPickImages` 是否存在 / 海浪进度」 | 同左，**没有按视口宽度切换** | `BottomNav.tsx:256-270`、`:281-285`、`:315`；`Layouts.tsx:172-177` |

### 9.2 与设备无关、但决定「结构感」的框架差异

2. **不合格**：`eligible === false` → `setConfirmed(false)` 并直接 return（`lib/admin.ts:138-142`），**一次 `/admin/self` 请求都不发**。
3. **合格**：`fetchAdminSelf()` → `GET /admin/self`（`:146`、`:32-43`）；401/403 → 返回 `null`（`:36-39`）；其它错误 → 抛出，被 `.catch` 置 `false`（`:150-152`）；非空 → `setConfirmed(true)`（`:147-149`）。
4. **初始值** `false`（`:136`）。
5. **返回值** `eligible && confirmed`（`:159`）。

即：**编号在 10000000–10000099（8 位）** 且 **`/admin/self` 非空** → 才 `true`。设计文档把这一组放在「设置 → 系统管理」（`docs/开发过程记录/S13-A-线上管理机制-审计与设计.md:190-207`）。
