## 7. S13-E：设计决定与审计结论摘要

**决定（2026-10-17 收尾新增，S13 的子阶段，不重排 S14–S17）**：
**账户 / 设置 / 账本级职责重整**，原则是**三层划分**——

| 层 | 装什么 |
|---|---|
| **用户级** | 个人资料、密码、恢复码、账号级邀请码额度、下载管理、软件更新、**默认币种** |
| **账本级** | **分类 / 标签 / 支付方式**、导出 / 导入、成员、分享、留言、编辑历史、账本信息 |
| **应用级** | 系统管理、版本公告、关于、法律条款 |

> **一句话原则：分类、标签、支付账户属于账本；账号属于人；平台属于应用。**

**审计结论（只读，逐条带行号：`S13-账本级数据归属与页面重整-审计.md`）**

1. **分类 / 标签 / 支付方式已经是账本级**——`book_id` 非空、唯一键含 `book_id`、
   API 全部按 `x-libellum-book` 指向的账本过滤、每本新账本自动生成自己的预设、
   离线副本按 `账号:账本` 分域。**所以 S13-E 不需要任何数据迁移。**
2. **真正的问题是入口位置**：三个管理页挂在「我的」下，路由是根级 `/categories` 等，
   而它们管的是**当前这本账**。
3. **"支付方式"不是"资金账户"**：全仓库没有余额 / 转账 / 对账模型；
   `balanceCents` 只是收支差。**资金账户要做得另立阶段。**
4. **两处结构性风险（不是漏洞）**：
   ① `queryKeys.ledger` 不带账本（`["ledger"]`），现在靠"切账本即整页重载"兜住，
   将来若做"不重载的切换"会串账；
   ② 分类三页**没有按角色隐藏写入口**，viewer 能点按钮，点了才 403（服务端安全）。

**范围**：纯界面归位 + 文案 + 角色隐藏 + 一条注释修正；**零迁移、零 API 变更**。
**更完整的范围与验收见** [`../开发计划.md`](../开发计划.md) 的 S13-E 一节。

8. **迁移只向前**：不要写回滚迁移，回滚应用不回滚数据库。

## 12. 安全纪律（这些不是建议）

1. **管理员五道校验**，少一道都不算通过（`admin/guard.ts:12-20`）：
   ① 有效会话 ② `admin_grants` 未撤销 ③ `admin_allowlist` 未撤销（**另一张表**）
   ④ 账号编号在首批号段 `10000000–10000099` ⑤ 账号可用且非 demo。
   **任何一道被关闭都按"拒绝"处理，不按"通过"处理。**
2. **管理员 ≠ 能看别人的账本。** 账本权限只来自 `book_members`；管理接口**不读任何账本内容**。
3. **生产改动必须先获批准**：部署、迁移、备份脚本、定时器、密钥、COS 策略、注册与邀请码规则。
4. **密钥不入库、不进仓库、不出现在输出里**：`.env` 权限 600、只在服务器上；
   命令行用环境变量传（`PGPASSWORD`），不写日志。
5. **敏感权限判断只许新增，不许改既有**（`AGENTS.md` §5.0）：
   要加判断可以，**动已有判断必须有所有者明确指令 + 说清行为差异 + 补测试**。
