## 产品要求

- 开始页面是同一页面的展开、收缩两种形态；海浪始终横跨全宽、保留在顶部。
- 展开态海浪代表高度约为可视高度 80%；收缩态约 15%。短横屏及设备安全区可为品牌可读性适当增加高度。
- 四层由深到浅：`#3f7059`、`#4f8a6d`、`#6aa78a`、`#96c4ac`。展示构图约 70/10/10/10；列表态遵循本轮「安静顶部栏」目标，适当收窄浅色区域（当前约 74.5/8.5/8.5/8.5，替代上一轮 61/13/13/13）。这是代表性高度关系，不要求所有横向位置等高。
- 三个过渡层在运动与切换中保持海浪代表高度约 5%–15% 的可见厚度，不消失、不交叉、不变成大色块。
- 波面柔和、舒展、连续；各层相互呼应但不完全复制。可以共享整体潮汐，再叠加细节差异。
- 展开态静置数秒能看出克制的流动；收缩态减弱。品牌不随潮汐晃动。
- 顶部始终深色覆盖，无浅色漏底、空白、矩形边缘或裁平的波面。
- 海浪收束与内容上移同时发生，反向展开时内容同步让出空间。只保留一套真实列表和一套连续移动的品牌，不用交叉淡化拼状态。
- 手势跟手，松手按位置和速度自然吸附。只有列表在顶部继续下拉才展开，普通列表滚动不误触发。
- 正文进入顶部区域后正确裁切，不能越过海浪出现在其上方。
- 展示态底部只有向上箭头和「上滑，进入我的账本」提示，不露真实卡片；提示可点击，以支持鼠标和键盘。
- 品牌展开时居中，收缩时连续移到左上；字号与顶部距离参考 1.4rem / 14px，并考虑安全区。
- 首次可展开、后续默认收缩；保持恢复上次账本的既有逻辑。
- 手机、iPad、桌面及横竖屏适配；减少动态效果时保留结构、停止环境波动并简化吸附。
- 保留创建、进入、分享、邀请、管理、同步等业务。不得为海浪修改无关后台或权限。
- 名称遵循最新项目决定。**2026-10-14 起产品名为 `Libevra`**（原名 `Libellum`，因域名原因更名；见 `Libevra品牌迁移记录.md`）。上一版这里写的是"未发现 Libevra 的采用记录，因此保留当前 Libellum"——**那个结论已经过期**。本页涉及品牌文字的实现见下方「品牌文字」一节；**海浪的形状、颜色、层次与动画机制一字未改**。

## 仍然有效的转场原则（1.10.01 从归档并入）

**这几条来自 `归档/账本空间-展示态-设计决定.md`，是所有者定过的、与具体参数无关的原则。**
**它们在被重做三次之后依然成立，所以在这里，而不在归档里。**

| # | 原则 | 所有者原话 / 理由 |
|---|---|---|
| **1** | **两种状态属于同一个页面**，不是两个独立页面 | *"这两种状态属于同一个页面，不是两个互相独立的页面，也不应该通过传统的页面跳转或整页覆盖实现切换."* |
| **2** | **不用页面跳转或整页覆盖** | 同上。**这条与"只保留一套真实列表、一套连续移动的品牌"是同一件事的两种说法。** |
| **3** | **不能以整页渐隐为主要转场** | ❌ 明确禁止：*"只是'绿色画面渐隐、白色页面渐显'"*；❌ 也禁止：*"简单把完整新页面从下面推上来覆盖旧页面"* |
| **4** | **目标是"海水退去、内容从海里显露"** | *"原本那片海正在退去，而账本空间就是从这片海里自然显露出来的."* |
| **5** | **展示态是欢迎体验，不是启动广告** | *"展示态是一个欢迎体验，而不是每次进入软件都必须经过的启动广告."* |
| **6** | **华丽用于欢迎与展示，简约用于日常与操作** | 属于第三类页面（特殊展示／沉浸式）。**这份华丽不得扩散到日常功能界面。** |
| **7** | **禁止炫技** | 禁止：剧烈晃动、**高频闪烁**、音频可视化／音乐播放器风格、大量元素同时无规律运动、**复杂 3D 场景** |
| **8** | **动画结束后按钮必须可用** | 过渡的终点是可操作，不是好看 |

**什么时候播放展示态**（来自同一份规格，仍然有效）：

| 场景 | 行为 |
|---|---|
| 新用户第一次进开始页面 | **展示态** |
| 上滑之后 | 列表态 |
| 以后从其他账本返回开始页面 | **默认直接列表态** |
| 在列表态顶部下拉 | 重新进入展示态 |
| 已有用户正常登录 | **仍走"上次使用账本"恢复逻辑，不被展示动画打断** |
| 用户主动返回开始页面 | 不必重新经历完整展示 |

## 可复用的实现机制（1.10.01 从归档并入）

> **⚠️ 这一节记的是"这个项目已经解决过一遍的东西"。**
> 明细页的「展示态 ↔ 明细态」是同一个模式（2026-10-10 完成并调过多轮），
> 它的实现在 `apps/web/src/lib/detailTransition.ts`，**开始页面复用同一套机制**。

| # | 机制 | 要点与理由 |
|---|---|---|
| 1 | **单一连续进度，而不是两套 DOM** | 中间态是**真实位置**，所有几何由 `--p` 用 `calc()` 推导。*"Everything in between is a real position, not a transition between two finished layouts."* |
| 2 | **进度存在 ref 里，每帧写 CSS 变量，不进 React state** | 手机以 60–120 Hz 发滚动与触摸事件，**那么频繁地重渲染就是把转场做卡的原因**。⚠️ **不要"改进"成 `useState`。** |
| 3 | **弹簧 + 速度上限** | `MAX_SPEED = 1 / 0.5`——**保证任何手势都不会让过渡快于 0.5 秒**。*"it is a speed limit rather than a physics fix"*。所有者当年为"卡顿"折腾好几轮，最后是这个上限解决的。 |
| 4 | **手势按落点分区，不按方向猜** | 区域内有横向滚动条的元素标 `data-h-scroll`，落在里面的手势**完全属于它**。*"Where the finger starts is not a guess."* |
| 5 | **手势速度用整段平均，不用最近采样** | *"fingers slow and drift in the last few milliseconds before they lift"*——最近采样是噪声最大的东西。 |
| 6 | **下拉要同时判断"在顶部"与"方向"** | 早期版本只判断"在顶部"，于是向上的拖动被吞掉：既不能滚，又被推到一个已经在终点的进度上。**这正是"不要把普通滚动误判成切换"那一条的实现。** |
| 7 | **桌面滚轮要累积增量** | `WHEEL_SCALE = 2400`；触控板一次手势会发几十个事件，**每个事件单独应用会过冲**。 |
| 8 | **记忆放模块级变量，不放 context** | 切 Tab 再回来能保持；**整页刷新会重置**（这也是要的）。 |
| 9 | **一代一主：`generation` 计数器** | 弹簧会在自己的回调里再次排程，**取消句柄后立刻起新弹簧会留下两个在写同一个进度**。每个弹簧带编号，编号不再是当前值就立即停止。 |

| `apps/web/src/index.css` | 页面 flex 布局、品牌插值、独立内容滚动区 |

进度 `p=0` 展开、`p=1` 收缩。海浪在正常布局中占据实际高度，下方提示区域从 20dvh 连续压缩到 0，余下空间成为同一列表的滚动窗口。列表窗口自身裁切正文，SVG 在海浪盒子下方保留曲线余量，不旋转、不整层缩放、不额外放大图形。顶部路径闭合在视口外，始终深色覆盖。

代表高度为 `80dvh → max(15dvh, 116px + safe-area-inset-top × 1.7)`。短横屏的 15% 容不下品牌与标语，因而使用可读性下限；层次比例始终以实际海浪高度计算。标准手机竖屏仍为约 15%。品牌字号 2.1rem → 1.4rem，收缩顶距 14px + 安全区，水平收缩终点跟随「我的账本」内容容器的实际左边缘（1.10.18起），不再独立使用20px左距。

本轮仅局部调整 `oceanGeometry.ts` 与提示箭头/文字。保留 SVG 三次曲线、页面布局、配色和手势机制。降低共享波形的振幅和整体倾斜，增加各层有界曲线的相位、波长与缓慢节奏差异，没有随机噪声。

以 `s=p²(3−2p)` 平滑收敛，边界为 `0.70 + 0.045s + layer × (0.10 − 0.015s) + shared + detail`。detail 的幅度从 0.022 降到 0.003，各层相同的 shared 在相邻差值中抵消。因此任一带宽下界为 `0.056 + 0.023s`，上界为 `0.144 − 0.053s`，全程仍在 5%–15% 内。展示态峰谷与层间宽度更错落；列表态减少浅色带面积、曲率与动态，不把明显波浪强行带入顶栏。公式与参数是当前选择，不是唯一方案。

环境动画连续推进时间，不按固定周期强制重置。页面隐藏时暂停，返回时不补跑隐藏时段；减少动态时停止环境动画，拖动仍更新曲线，松手直接到目标态。品牌只读取进度，不读取潮汐时间。

手势锁定开始时的列表顶部条件，有 8px 方向阈值，横向滑动和输入框不抢占。从列表中部开始的向下滚动始终属于列表，需到顶后重新下拉。滚轮在收缩态向下滚动正常交给列表。修正了此前滚轮释放方向以及触摸速度到进度速度的符号；未修改共用物理函数。触摸中断、横向放弃与 resize 会恢复吸附。展开时内容区 inert，避免键盘焦点进入屏外列表。

## 被替换的旧假设与历史经验

- 旧文档将各层独立摆动当成必要条件，导致难以同时满足厚度与动态。共享运动允许明显起伏，并不必然让曲线平行。
- “振幅只能 1.5–2vh”“唯一办法是拉开层间距离”只适用于特定的独立振幅最坏估计；不适用于共享位移在差值中抵消的情况。
- 固定曲线的纯缩放确实不能改变端点比例，但路径形变可以；没有两套路径交叉淡化的必要。
- “至少 120 个点才能柔和”不是通用结论。三次曲线可以用更少的段数获得连续切线。
- `scaleY`、固定定位、旋转三度、CSS 变量均非产品要求。本次保留变量驱动布局，但替换了独立缩放及旋转。
- Tailwind、CSS 作用域、错误滚动引用曾是具体故障，应看当时产物。不能将所有静止、平直或卡顿都归因于同一个原因。
- 仍有价值的检查：顶部覆盖、曲线裁切、全文是否混入注释、SVG 显式宽高、内容是否同步移动、滚动归属是否读取真实 scroller。编译成功不能替代视觉检查。

## 1.10.10 提示与页脚补充

产品要求：海浪完整展开时向上箭头及「上滑进入我的账本」必须可见；展开早中期隐藏、接近完成淡入，反向拖动连续；短列表Footer靠底、长列表Footer自然随内容滚动。

实际实现：p=0为完整展开，p=1为收缩；提示opacity=clamp(0,1-p/0.18,1)，p>=0.18为inert。提示在独立绝对定位层，位于视口底部20%，不在SVG或波面裁剪容器内。列表顶部保留20dvh*(1-clamp(p))的展示空间，与海浪同步退去。Flex列增长链和Footer的margin-top:auto实现短长列表布局，底部留20px+安全区。
