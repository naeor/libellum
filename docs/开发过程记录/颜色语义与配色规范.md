## 0. 一句话结论

**Libevra 的颜色系统已经是健康的——token 覆盖完整、没有乱用的颜色。**
真正缺的不是颜色，是**状态**和**两处对比度**：

| 发现 | 数据 |
|---|---|
| ✅ **颜色工具类全部指向已定义 token** | **0 处**指向未定义的 token（除 Tailwind 内置的 `white`/`transparent`） |
| ✅ **硬编码 HEX 已被守卫拦住** | 全站只存在于 4 个豁免文件里 |
| ⚠️ **状态颜色没有 token** | 聚焦环写了 **10 遍**、遮罩有 **2 种深度**无名、阴影是 **2 个匿名 `rgba()`**、**`Button` 完全没有焦点态** |
| ⚠️ **`muted` 未达 AA** | **4.14:1**（需 4.5:1），而它是**全站第二大**的文字颜色（295 处） |
| ⚠️ **图表坐标轴文字仅 2.67:1** | `accent-ink` 承担刻度信息，**远低于 AA** |

**⚠️ 本轮修掉了「状态没有 token」，并把两处对比度问题连同精确数字一并报告——
因为改 `muted` 会让 295 处文字同时变深，那是视觉决策，不是整理。**

### 1.4 ⚠️ 为什么保留 `ink` / `muted` 这些旧名字

所有者要求区分「`text-primary` / `text-secondary`」这类语义概念，**但也要求
"不要让原本已存在的 `ink`、`muted` 与新名字产生互相竞争的两套系统"**。

**`ink` 和 `muted` 已经是语义名**——它们描述**用途**（"主要文字"/"次要文字"），不描述外观。
`text-primary` 只是**同一个概念的另一个词**。**为它建第二个名字，就是制造所有者明确禁止的第二套系统。**

**所以约定是**：概念名 → 既有 token 的对应关系写在这里，**代码里继续用 `ink` / `muted`**。

| 所有者提到的概念 | 本项目的 token | 说明 |
|---|---|---|
| `text-primary` | `--color-ink` | 主标题与正文 |
| `text-secondary` | `--color-muted` | 次要信息 |
| `text-tertiary` | `--color-accent-ink` | ⚠️ **仅图表**，见 §4.2 |
| `text-on-brand` | `--color-white`（在 `bg-brand` 上） | 见 §4.1 |
| `text-action` | `--color-brand-dark` / `--color-brand` | 见 §3.3 |
| `text-danger` | `--color-danger` | |
| `text-disabled` | **无 token** | 用 `disabled:opacity-45`，见 §2.3 |

## 2. 正式语义 token（含本轮新增）

### 2.1 ✅ 新增的「交互状态」组

**这是本轮的核心补充。** 审计发现：**颜色被想过，"状态"没有**——

| 新 token | 值 | 用途 |
|---|---|---|
| `--color-overlay-soft` | `rgb(36 49 43 / 0.25)` | 对话框 / 底部面板遮罩（3 处） |
| `--color-overlay` | `rgb(36 49 43 / 0.35)` | 月份选择 / 明细页遮罩（2 处） |
| `--shadow-card` | `0 1px 2px rgb(36 49 43 / 0.04)` | 卡片投影（1 处） |
| `--shadow-sheet` | `0 -8px 30px rgb(36 49 43 / 0.14)` | 底部面板投影（1 处） |

**⚠️ 这四个的值与原代码**逐字节相同**——本轮只给它们名字，**不动画面**。
它们原本是 `bg-ink/25`、`bg-ink/35` 和两个匿名 `rgba()`。

**⚠️ 为什么阴影要用墨色而不是黑色**：`rgba(36,49,43,…)` 就是 `ink`。
**用文字色染的投影，看起来和整页是同一束光**；中性黑投影会发灰。原值本来就是对的，**缺的只是名字**。

### 2.2 ⚠️ 聚焦环：**没有**新建 token，而这也是有意的

**我一开始新建了 `--color-focus-ring`（与 `--color-brand` 同值），随后把它删掉了。**

⚠️ **理由**：所有者的原则确实是*"不同语义的颜色即使当前色值相同，也允许分别命名"*——
**但也要求"不要为了凑齐设计系统而增加没有使用场景的颜色"**。
聚焦环实际用的颜色是 **`brand-soft`（浅绿光晕），不是 `brand`**：

- 全站 **10 个输入控件**都写 `focus:ring-4 focus:ring-brand-soft`；
- 新加的 `Button` 焦点环也用 `focus-visible:ring-brand-soft`。

**所以 `--color-focus-ring` 从定义的那一刻起就没有任何使用者。**
**一个没有使用者的 token 会腐烂**——它留在 `@theme` 里，看起来像"还有个聚焦环颜色可以用"，
而真正的聚焦环是另一个。**删掉它比留着更诚实。**

**⚠️ 同样的判断也用在 `--color-overlay-strong` 上**：扫描页有一个 `bg-ink/75`，
但它不是遮罩，是**照片上的深色 ✕ 圆形按钮**（带白色图标）。
**把它命名成遮罩就是给东西起了个说谎的名字**，所以没建第三个遮罩 token。

### 2.3 ⚠️ 禁用状态：**有意没有 token**

全站 **24 处**禁用样式，一律是 `disabled:opacity-45` **加** `disabled:cursor-not-allowed`。

**⚠️ 用透明度而不是灰色 token，是有理由的**：
禁用态出现在**四种不同背景**上（品牌绿按钮、浅绿按钮、白卡片、绿头），
**一个灰色 token 不可能在四种背景上都保持"看起来禁用"**。降低不透明度让**按钮自己变淡**，
所以在任何背景上都读得出"这个不能点"。**这是对的，本轮没有改。**

## 3. 颜色角色与用途

### 3.1 品牌颜色

| 角色 | token | 用途 |
|---|---|---|
| 主品牌色 | `--color-brand` | 一级页绿头、主按钮底、选中态、聚焦边框 |
| 深品牌色 | `--color-brand-dark` | **绿色文字操作**（悬停后更深）、主按钮 hover 底 |
| 浅品牌底 | `--color-brand-soft` | 次级按钮底、聚焦环、分类圆标底、选中 chip |
| 分类圆标文字 | `--color-category-ink` | ⚠️ **专用**，见 §5.1 |

### 3.2 ⚠️ 五个绿为什么不能合并

| 绿 | 值 | 为什么独立 |
|---|---|---|
| `brand` | `#55997a` | 品牌识别本身 |
| `brand-dark` | `#447d63` | **在浅底上要读得清**——绿文字不能直接用 `brand`（3.27:1） |
| `brand-soft` | `#edf5f0` | **是背景不是前景**，与上面两个不构成竞争 |
| `category-ink` | `#3f7059` | **专门为 36px 圆标调过对比度**（5.15:1），见 §5.1 |
| `accent-ink` | `#8fa39a` | **图表的低强调文字**，见 §4.2 |

**⚠️ 合并它们会造成实际损害**：`brand-soft` 是背景，`brand` 是前景，**合并 = 文字消失在底色里**。

### 3.3 绿色文字操作

**统一规则**：默认 `text-brand` 或 `text-brand-dark`，悬停加深。

| 实测用法 | 次数 |
|---|---|
| `hover:text-brand-dark` | 14 |
| `hover:text-ink`（次要操作转主色） | 24 |
| `hover:border-brand` | 3 |

**⚠️ 「查看全部 ›」这类操作有两个绿**：`text-brand`（12px 小字）与 `text-brand-dark`（正文尺寸）。
**这是有意的层次**，不是不一致：**小字用亮一点的绿保持可见，正文用深绿保证可读。**

## 4. ⚠️ 对比度审计（WCAG 2.1 AA）

### 4.1 通过的部分

| 组合 | 对比度 | |
|---|---|---|
| `ink` on `canvas` | **13.16:1** | ✅ |
| `ink` on `surface` | 13.56:1 | ✅ |
| `white` on `danger` | 4.65:1 | ✅ |
| `white` on `danger-dark` | 6.20:1 | ✅ |
| `danger` on `surface` | 4.65:1 | ✅ |
| `brand-dark` on `canvas` | 4.68:1 | ✅ |
| `brand-dark` on `surface` | 4.82:1 | ✅ |
| **`category-ink` on `brand-soft`** | **5.15:1** | ✅ 分类圆标 |
| `white` on `brand-dark` | 4.82:1 | ✅ |

### 4.2 ❌ 需要所有者决定的三处

**① `muted` 未达 AA —— 影响最大的一处**

| 背景 | 实测 | 需要 |
|---|---|---|
| `canvas` | **4.14:1** | 4.5:1 |
| `surface` | **4.27:1** | 4.5:1 |
| `brand-soft` | **3.84:1** | 4.5:1 |

**⚠️ 它用在 295 处**——日期、编号、说明、元信息，**全站的次要文字都是它**。

**⚠️ 但这一轮没有改，因为它会让 295 处文字同时变深**——那是视觉决策，不是整理。

**建议的最小改动**（沿原色相加深，**不换色相**）：

```
--color-muted:  #6b7f76  →  #60726a      （加深 10%）
结果：canvas 4.96:1 ／ surface 5.11:1 ／ brand-soft 4.60:1   ← 三个背景全部达标
```

**请所有者先看一版再决定**：`muted` 从"柔和的灰绿"变成"稍深的灰绿"，
**在浅色底上仍明显弱于 `ink`（13:1），层级不会被破坏。**

**② 图表坐标轴文字仅 2.67:1**

`--color-accent-ink`（**审计当时是 `#8fa39a`**）是坐标轴与图例的文字色，**对比度 2.67:1，远低于 AA**。
**⚠️ 这处已在 1.10.17 修好：文字升到 `#5f7268`（5.13:1 ✅），而线条拆到 `--color-chart-rule` 保持浅色。**
**本节记录的是审计当天的事实，不是当前值。**
它承担的是**真实信息**（刻度值、图例名称），不是装饰。

**⚠️ 建议改到至少 4.5:1**（约 `#5f7268`），**但这会让图表标签明显变深**，需所有者确认。
**⚠️ 本轮未改。**

**③ 绿头副标题 2.74:1**

`text-white/80` 在 `bg-brand` 上实际是 `#ddebe4`，**2.74:1**。
它是每个一级页的副标题（"以下结果由已记录的账目计算得出。"），**是真实说明文字**。

**⚠️ 根因是品牌绿本身较亮**：纯白在 `bg-brand` 上也只有 **3.37:1**，
所以**无论怎么调透明度都到不了 4.5:1**——除非加深品牌绿或改副标题字号。

**本轮未改。** 三个可行方向（需所有者选）：
1. 保持现状（3.37:1，**标题 20px/600 属大字，AA 要求 3:1，标题是达标的**；只有副标题不达标）；
2. 副标题改用纯白（2.74 → 3.37，**改善但仍在 AA 之下**）；
3. 加深品牌绿（**会改变整个品牌识别，不建议**）。

**⚠️ 我的建议是 1 或 2，并在文档里如实记为已知限制**——因为**副标题是补充说明，不是操作入口**。

### 4.3 ⚠️ 透明度修饰符的隐藏风险

| 写法 | 实际渲染 | 对比度 | 位置 |
|---|---|---|---|
| `placeholder:text-muted/60` | `#a6b2ad` | **2.19:1** | 7 处输入框/文本域 |
| `placeholder:text-muted/50` | `#b5bfbb` | **1.89:1** | 记账金额输入框 |

**⚠️ 这两处是占位符（placeholder）**。WCAG 未对占位符单独设阈值，但**它是用户看到的唯一提示**，
而在「金额」「备注」这类字段上，**占位符常常是唯一说明**。

**本轮未改**（改它会同时牵动 8 个输入框的观感）。**记录在此供决定。**

## 9. 以后如何新增语义色

### 9.1 三条规则

1. **先问"这是什么用途"，再问"什么颜色"**——token 名说职责，不说外观。
   ⚠️ `--color-green` 是错的，`--color-brand` 是对的；**"品牌"能活过换色，"绿"不能。**
2. **已有的语义能覆盖就不要新增**。判断标准是**"它是不是一个独立职责"**，**再加上"它是否真的与既有值不同"**。
   ⚠️ **聚焦环正好说明这条要两面看**：它**是**独立职责（键盘可达性），但
   **全站只有一个聚焦色，且与 `brand-soft` 完全相同**——新建一个同值 token
   **不增加任何信息，只多一个要同步的地方**。所以它是**一条规则**（见 §2.2），不是一个 token。
   **等真的出现第二种聚焦环，再建 token 也不迟。**
3. **新增必须同时更新本文档与 `colors.test.ts` 的白名单**（如适用）。

### 9.2 ⚠️ 典型错误示例

**错误 ①：同一个危险操作使用多种红色**

```tsx
// ❌ 三个地方、三种红
<button className="bg-[#c0392b]">退出账本</button>
<span className="text-red-600">删除失败</span>
<p style={{ color: "#e74c3c" }}>无法移除成员</p>

// ✅ 一个语义，一个来源
<Button variant="danger">退出账本</Button>
<span className="text-danger">删除失败</span>
<p className="text-danger">无法移除成员</p>
```

**⚠️ 这正是 `colors.test.ts` 要拦的东西**——它会把前一种写法在测试里报出来。

**错误 ②：把背景色当文字色用**

```tsx
// ❌ brand-soft 是背景，拿它当文字就消失了
<span className="text-brand-soft">说明</span>

// ✅ 文字用为文字调过的深档
<span className="text-brand-dark">说明</span>
```

**错误 ③：为了"看起来一样"合并两个绿**

`brand-soft`（背景）与 `brand`（前景）**可以同时出现在一个组件里而不冲突**——
圆形分类标识就是 `bg-brand-soft` + `text-category-ink`。
**合并它们等于让文字消失在底色里。**

**错误 ④：给禁用态加深灰色**

```tsx
// ❌ 禁用态出现在四种背景上，一个灰色不可能都成立
<button className="disabled:text-gray-400">

// ✅ 让按钮自己变淡——在任何背景上都读得出"不能点"
<button className="disabled:opacity-45 disabled:cursor-not-allowed">
```

### 9.3 ⚠️ 自动检查的边界

`colors.test.ts` **只拦硬编码 HEX**，而且**必须保留豁免**：
海浪、图表、QR、标签色都是**有理由的例外**。

**⚠️ 不允许"一刀切禁止所有颜色字面值"**，理由见 §5——那四个豁免**不是偷懒，是需求**。

### 11.3 ⚠️ 一个 token 干两件相反的事

`accent-ink` 原本**同时**是图表**文字**色和**网格线**色。这两件事的要求正好相反：

- **文字要够深**（AA 4.5:1）——被人读；
- **网格线要够浅**（`strokeOpacity` 0.22）——**是参考不是数值，要退到数据后面**。

**⚠️ 如果只把 token 调深，网格线会一起变深，结果是「网格比柱子还显眼」**——
修好了一件事，弄坏了另一件。**所以拆成 `accent-ink`（文字）与 `chart-rule`（线），
线的值一个字节没动。**

> **⚠️ 通用的教训：同一个变量被两处引用，不代表这两处是同一个语义。**

### 11.4 ✅ 聚焦环的最终规则（**修正了本文档此前的自相矛盾**）

**⚠️ 原文档在 §2.2 写「不需要独立 token」，却在 §9.1 写「`focus-ring` 值得新建」——这是矛盾的。
现在统一为一条规则：**

| 项 | 最终规则 |
|---|---|
| 颜色 | **复用 `--color-brand-soft`**（`#edf5f0`），**不新建 token** |
| 输入控件（10 处） | `focus:ring-4 focus:ring-brand-soft` |
| 按钮（`Button`） | `focus-visible:ring-4 focus-visible:ring-brand-soft` |
| 宽度 | **4px，全站唯一值** |

**为什么 `focus` 与 `focus-visible` 并存不是不一致**——**它们回答的是不同问题**：
输入框**只有在获得键盘焦点时**才可能被聚焦（点进去也是要打字），所以 `focus` 就是对的；
按钮**鼠标点击也会聚焦**，用 `focus-visible` 才能做到**「鼠标点不出现环、键盘走出现环」**。
**两者都由键盘驱动、行为一致，只是触发条件按控件类型各取所需。**

**为什么没有 token**：全站**只有一个聚焦色**，且与 `brand-soft` 完全相同。
**新建同值 token 不增加信息，只多一个要同步的地方。**
（**待真的出现第二种聚焦环，再建 token 也不迟**——这是 §9.1 第 2 条的判据。）

### 11.5 ⚠️ 禁用状态的适用边界，以及一个**显式限制**

**统一为 `disabled:opacity-45`（24 处）**，即 `Button` 的默认值。
改前有 **40 / 45 / 50 / 60 四种**，差别只是「谁写的」，没有各自的理由。
**⚠️ 60 那三处是往下调的**——1.93:1 与可用态 3.27:1 太接近，会让人以为还能点。

**适用范围（不是绝对规则）**：

| 场景 | 合适吗 | 说明 |
|---|---|---|
| 品牌绿按钮 | ✅ | 变淡后与可用态明显不同 |
| 浅绿 / 白色底上的操作 | ✅ | 同上 |
| **禁用态仍需阅读的长文字** | ⚠️ | **应改用 `text-muted` + 其他禁用线索，而不是靠降低不透明度** |

**⚠️ 实测到的限制（如实记录，未修）**：

| 状态 | 按钮底 vs 页面底 | 按钮内文字 |
|---|---|---|
| 可用（品牌绿） | 3.27:1 | 3.37:1 |
| **禁用（opacity-45）** | **1.63:1** | **1.35:1** |

**⚠️ 两个数字都低于 3:1。** 但这是**有意的取舍**：
禁用控件的**首要职责是「看起来不能用」**，若把禁用态提到 3:1（约 `opacity-90`），
它会与可用态几乎一样——**那才是真正的可用性故障**。
WCAG 1.4.3 **豁免禁用控件**，且这里的文字是**「已知不可用」的说明而非信息**。
**⚠️ 仍然记录在此，因为「按钮里的字几乎看不见」是一个真实的观感代价，不值得假装它不存在。**

### 11.6 自动化检查的实际覆盖能力

`colors.test.ts` 现在有 **4 条**（原 2 条）：

| # | 检查 | 覆盖 |
|---|---|---|
| 1 | **硬编码 HEX** | ✅ 组件里出现 `#rrggbb` 即失败 |
| 2 | **硬编码 `rgb()` / `rgba()`**（**本轮新增**） | ✅ 补上了此前的漏洞 |
| 3 | **白名单条目有效性** | ✅ 白名单里的颜色**必须带透明度**——是光效不是主题色 |
| 4 | **检查本身真的扫到文件** | ✅ 防止守卫悄悄失效 |

**⚠️ 第 2 条抓到了一个真实遗漏**：`detail-motion.css` 的 `.detail-currency-card`
用 `rgb(255 255 255 / 0.14)` 做**明细页绿头上的白色玻璃**。
**它是光效不是主题色**——职责是「在身后那个**每帧都在插值**的绿底上盖 14% 白」，
而 token 只能是固定颜色。**所以进入白名单并写明理由，而不是为了整齐把它塞进调色板。**

**⚠️ 明确不做的事（也是所有者给的选项）**：不检查**内联 style**、**Tailwind 内置颜色名**、
**任意透明度组合**。理由与代价写在测试注释里：

- 内联 style 在这里**是合法的**（`tag.color` 是**用户数据**，`heatColor()` 是**计算值**）；
- `text-white`（对）与 `text-red-500`（错）**同为内置色，按名字分不开**，要维护允许清单；
- `text-white/80` **不是错的**，禁掉它只会逼人换个写法而不会更可读。

**所以这些限制写在本文档（§4.3、§9.3），让读者拿到「为什么」，而不是编码成会误报的规则。**
